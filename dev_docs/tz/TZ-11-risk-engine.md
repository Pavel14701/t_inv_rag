# TZ-11. Risk Engine — детерминированный риск-контур

## 1. Контекст

Тезис проекта — «решения принимает только детерминированный код» — неполный без Risk
Engine: сейчас риск-параметры (TP/SL, ATR-мультипликаторы) разрознены (`ai/src/features.py`,
конфиги), а лимитов позиций/просадки нет вовсе. README обещает «жёсткий детерминированный
риск-менеджмент» — TZ-11 закрывает этот пробел.

## 2. Место в системе

```
DSL-сигналы (+P(win)) → Risk Engine (TZ-11) → приказы (объём, SL/TP) → исполнение (TZ-04 движок)
```

Вне контура: LLM не имеет ни импорта, ни транспортного доступа (TZ-09 не содержит
команды изменения лимитов — проверяется тестом на схему очередей).

## 3. Требования

1. Пакет `risk/` (workspace-член `dte-risk`, deps: numpy/pyyaml) — либо секция в
   `strategies/`; решение фиксируется при старте.
2. **Конфигурация**: `configs/risk.yaml` (frozen dataclass, как `ai/src/config.py`);
   переопределение только кодом/конфигом, не в рантайме.
3. **Правила** (все обязательные, нарушение = сигнал отбрасывается + счётчик в отчёте):
   - обязательные SL/TP на каждом входе (ATR-мультипликаторы, каузальные);
   - лимит позиции: % капитала и max размер в штуках;
   - дневной лимит убытка и MaxDD-стоп (закрытие позиции + пауза, TZ-04 п.4.4);
   - лимит открытых позиций/корреляции (опционально, v1 — max позиций).
4. **API**: `check(signal, portfolio, cfg) -> Decision{approve|reject, reason, size}` —
   чистая функция, без IO, без времени внутри (время — параметр).
5. Интеграция: бэктест TZ-04 вызывает check() на каждом сигнале; live-контур (TZ-10) —
   тот же check() (принцип №2 TZ-00: один движок на три потребителя).

## 4. Критерии приёмки

- Тесты граничных случаев: SL/TP отсутствуют → reject; превышение дневного убытка →
  reject всех сигналов до конца дня; MaxDD-стоп; size=0 при пустом капитале.
- Тест-инвариант: ни один путь кода не позволяет обойти check() (без approve нет приказа).
- Тест схемы очередей TZ-09: нет сообщения «изменить лимиты».
- `uv run --package dte-risk pytest` зелёный.
